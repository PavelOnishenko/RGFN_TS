# Действующие правила

Ревизия: 3. Обновлено: 12 октября 2026 года.

Это короткая актуальная политика. Подробности процесса — в
[WORKFLOW.md](WORKFLOW.md), архитектуры — в [VISION.md](VISION.md).
Прямые указания пользователя имеют приоритет. Старые правила браузерной реализации
не переносятся автоматически на Godot-код.

## Работа агента

| ID | Правило |
| --- | --- |
| R-001 | Выполнять одну маленькую назначенную задачу; сохранять её ID между исправлениями |
| R-002 | STATUS.md — короткий единственный текущий учёт; одновременно один in_progress и не более одного непринятого реализованного шага; старые завершённые записи архивируются |
| R-003 | Завершать шаг проверяемым результатом и пакетом ревью; accepted ставить только по явному принятию/поручению продолжить |
| R-004 | После замечаний исправлять тот же шаг; не строить следующий зависимый код на непринятом результате |
| R-005 | Новое постоянное указание сохранять здесь с ревизией; архитектурное решение — также в DECISIONS.md |
| R-006 | Читать ближайший нужный контекст, избегать повторного анализа всего проекта; не реализовывать roadmap целиком из одного поручения на маленький шаг |
| R-007 | Писать простой читаемый код; лимиты строк/файлов не оправдывают сжатие и искусственную декомпозицию |
| R-008 | Не смешивать новую механику, большой перенос файлов и соседний рефакторинг в одном шаге |
| R-009 | Проверять изменение подходящими средствами; фиксировать фактический результат, различать непроверенное и прошедшее |
| R-010 | Не создавать коммиты, PR или публикации без соответствующего поручения; не менять чужой локальный diff |

## Как менять правила

Уточнить действующее правило или добавить следующий свободный ID; ID не
переиспользовать. Сохранить краткую причину и дату в истории ниже, повысить ревизию.
Для временного исключения записать в STATUS.md правило, основание, границы
и момент окончания исключения; основную норму не переписывать.

Правило, придуманное агентом и требующее существенного изменения привычного
порядка работы, обозначить как предложение до принятия. Обычные локальные
реализационные решения принимать самостоятельно внутри порученного шага.
