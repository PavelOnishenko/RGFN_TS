# BOOT-001 — совместимые версии и воспроизводимый старт

Статус и результат хранятся в [STATUS.md](../STATUS.md).

После TURN-001 независимые проекты ядра/тестов и их версии уже существуют
(D-009). Не создавать их повторно. Оставшаяся часть этой задачи — проверить
подключение Godot .NET и ограничения экспорта; при необходимости изменить
техническую базу отдельным обозримым шагом.

## Цель

Выбрать совместимые Godot .NET, .NET SDK и target framework,
зафиксировать будущий маршрут сборки и проверить доступность инструментов.
Результат — техническая запись, по которой следующий агент создаст проекты
без повторного выбора стека.

## Предпосылки

- Пользователь назначил этот шаг.
- Прочитаны актуальные правила, процесс и структура репозитория.
- Учтён имеющийся локальный diff; документационный пакет можно уточнить
  по прямым замечаниям пользователя.

## Объём

- Проверить доступные dotnet/Godot, их версии и поддержку нужного сочетания
  по актуальной официальной документации.
- Выбрать стабильную Godot с поддержкой .NET; закрепить конкретную версию
  редактора и совместимого SDK/framework. Учесть предполагаемый десктопный экспорт.
- Использовать NUnit для независимых тестов ядра по решению пользователя.
  Проверить совместимые версии NUnit и средств запуска через dotnet test;
  выбор самого тестового фреймворка уже сделан.
- Добавить результат в раздел запуска REPOSITORY.md и решение D-002/D-003
  либо новое техническое решение в DECISIONS.md; обновить STATUS.md.
- Записать реальные команды проверки версии и будущие команды сборки с папками.

Установка инструментов, создание всех проектов, художественный выбор и
Steam-публикация не входят в этот шаг. Если инструменты отсутствуют,
зафиксировать отдельную задачу установки/подготовки и зависимость bootstrap.
Отсутствие инструмента не обозначать как успешно пройденный запуск.

## Критерии готовности

- Конкретные версии и основания совместимости записаны со ссылками на источник.
- Наличие/отсутствие инструментов и ограничения экспорта проверены фактически.
- Выбранный SDK/framework согласован для core, Godot и tests.
- Следующий шаг BOOT-002 может создать один проект без новых архитектурных решений,
  либо назван конкретный предварительный шаг подготовки.
- Существующие TypeScript-файлы и команды не изменены.

## Проверка и ревью

Показать фактические выводы команд версии, источники совместимости и
небольшой diff технических решений. Не запускать npm test ради изменения
описания будущего стека. Передать человеку проверяемый выбор;
следующий кодовый шаг выполняется по принятии/поручению.
