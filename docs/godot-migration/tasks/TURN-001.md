# TURN-001 — первый перенос теста инициализации ходов

Статус хранится в [STATUS.md](../STATUS.md).

## Цель и исходный контракт

Перенести один существующий тест `TurnManager initializes turns with only active
living entities` из `test/systems/turnManager.test.js`.
Исходное состояние: активный живой игрок, затем активный мёртвый противник.
Действие: инициализация очереди. Обе исходные проверки:

1. Текущий участник — тот же объект игрока.
2. Сейчас ход игрока.

Название теста шире фактических проверок: он не проверяет всю очередь,
неактивных участников, переход хода или последующую смерть. Эти сценарии
не считаются перенесёнными после успешного выполнения данного теста.

## Объём

- Минимальная подготовка двух .NET-проектов: независимого ядра и NUnit-тестов.
- Закрепление фактически используемых SDK/framework и пакетов тестирования.
- Минимальные данные участника и инициализация очереди в ядре.
- Один NUnit-тест с двумя эквивалентными утверждениями.
- Привязка рядом с исходным тестом и частично переносимым методом к карте
  соответствий; TypeScript-правило и исходные assertions не меняются.
- Учёт результата, цикла red/green и неперенесённых сценариев.

Подготовка проектов входит в это поручение: без неё первый исполняемый тест
невозможен. Полный BOOT-001 и сцены Godot не объявляются завершёнными.
Установка отсутствующего SDK допустима в игнорируемый work/, вне игровых исходников.
Идентичность игрока задаётся явно, без распознавания имени C#-класса.

## Предварительное размещение

- `game/core/Rgfn.Core.csproj` и `game/core/Combat/TurnManager.cs`.
- `game/tests/Rgfn.Core.Tests/Rgfn.Core.Tests.csproj` и
  `game/tests/Rgfn.Core.Tests/Combat/TurnManagerTests.cs`.
- `game/global.json`; небольшой тип участника может остаться в файле правила.

## Проверка

Сначала сборка TypeScript и запуск только исходного теста по имени.
Затем NUnit-тест должен упасть по ожидаемой причине отсутствия поведения,
после реализации — пройти. Финально проверить независимую сборку ядра,
связанный исходный test-файл и отсутствие генерируемых файлов в diff.
Команды и фактические результаты записать в STATUS.md.

## Ревью

Прочитать минимальную реализацию и два NUnit-утверждения, сверить с оригиналом.
Зелёный тест означает исполнение контракта; принятие человеком учитывается
отдельно. Остальная логика TurnManager остаётся в очереди.
