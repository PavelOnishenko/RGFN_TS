# Структура единого репозитория

## Один репозиторий, две реализации на время перехода

Текущая TypeScript-версия остаётся в корне. Новая версия размещается в game/.
Это позволяет сверять поведение и документацию, не перемещая одновременно
старый код, пути импорта, тесты и GitHub Pages. Общая история связывает причины
изменения правила с его реализацией в новой игре.

В текущем tsconfig.json компилируется js/**. Скрипт веб-развёртывания копирует
явный список dist, css, data, index.html и style.css. Предложенный game/
не входит в эти пути. Фактическое сосуществование проверяется при bootstrap.

## Целевая схема

Созданы game/core/Rgfn.Core.csproj, game/tests/Rgfn.Core.Tests/Rgfn.Core.Tests.csproj
и game/global.json для первого теста. Остальная схема — план размещения.
Пустые папки и заранее придуманные классы создавать не требуется.

```text
/
  AGENTS.md                       # короткий вход для любого агента
  README.md                       # как запустить реализации и найти план
  docs/
    godot-migration/               # видение, правила, roadmap, состояние, задачи
    ...                           # история и документация текущих механик
  js/ test/ data/ css/             # текущая TypeScript-версия
  index.html style.css
  package.json package-lock.json tsconfig.json scripts/
  .github/workflows/
  game/
    Rgfn.sln                      # решение .NET; точный формат фиксирует bootstrap
    global.json                   # согласованная версия SDK и политика roll-forward
    core/
      Rgfn.Core.csproj             # обычная C#-библиотека без Godot
      Session/ World/ Time/
      WorldSimulation/ Combat/ Quests/ Characters/ Items/ Content/
    godot/
      project.godot               # открывать именно эту папку в Godot
      Rgfn.Godot.csproj            # ссылка на соседний core-проект
      Scenes/
        Main/                     # сцена и её небольшой C#-скрипт рядом
        World/ Village/ Battle/ Hud/
      Adapters/                   # ввод, хранение, загрузка и представления
      Content/                    # определения Resource и загрузчики
      Assets/                     # готовые для игры изображения, звук, шрифты
      export_presets.cfg          # воспроизводимые настройки без секретов
    tests/
      Rgfn.Core.Tests/
        Rgfn.Core.Tests.csproj
        World/ Time/ Combat/ Quests/ ...
      godot/                      # сценарии интеграции с движком, когда понадобятся
    assets-source/                # исходники редакторов, когда появятся
  work/                           # локальные временные исследования; игнорировать
  artifacts/                      # локальные сборки/отчёты/экспорты; игнорировать
```

Если выбранный SDK предпочитает другой формат solution, обновить эту схему
и команды одной небольшой задачей. Версии Godot .NET, SDK, целевого .NET
и NUnit со средствами запуска фиксируются в BOOT-001 по фактической совместимости.
Тестовый фреймворк уже выбран пользователем: NUnit (решение D-007).

Для TURN-001 фактически проверены SDK 8.0.425, target framework net8.0,
NUnit 4.6.1, NUnit3TestAdapter 5.0.0 и Microsoft.NET.Test.Sdk 17.14.1.
SDK закреплён в game/global.json с rollForward=latestPatch.
Проверка сборки Godot .NET и экспорта остаётся отдельной частью BOOT-001.

## Почему core и tests находятся вне Godot-проекта

Godot импортирует содержимое своей папки, а C# SDK включает исходники по правилам
проекта. Соседнее размещение не даёт случайно включить код ядра и тестов второй раз
в Godot-сборку или импортировать исходники ассетов. Связь задаётся ProjectReference.

Направления зависимостей:

```text
Rgfn.Godot -> Rgfn.Core
Rgfn.Core.Tests -> Rgfn.Core
```

Ядро не имеет обратной ссылки на Godot. Один core-проект достаточно;
модули внутри него разделяются по игровой ответственности.

## Код, данные и ассеты

- В core размещать правила и состояние рядом с владеющей механикой.
  Общий Utils не используется как место для кода без понятного владельца.
- Скрипт сцены и .tscn по возможности хранить рядом. Сцена отвечает за представление;
  расчёты боя и расписаний остаются в core.
- У определения контента один редактируемый источник. Если это .tres,
  C#-представление создаётся загрузчиком, а не поддерживается вручную параллельно.
- Небольшие текстовые наборы имён/шаблонов можно перенести из data/ отдельным шагом,
  когда ими начнёт пользоваться новая версия. Общий каталог для двух клиентов
  появляется только при реальном совместном использовании и проверке путей сборки.
- Исходники графических/звуковых редакторов хранить вне game/godot/;
  экспортированные игровые файлы — в Assets/. Большие бинарные файлы при необходимости
  переводить на Git LFS отдельным решением.
- Спрайты и звук подключать по визуальному ключу/адаптеру. Ядро не хранит Texture2D
  или PackedScene. Игровые и визуальные параметры не смешивать в одном Theme.

## Что хранить в Git

Хранить C#-исходники, проекты и solution, project.godot, .tscn, .tres,
ассеты, настройки импорта рядом с ассетами и генерируемые выбранной версией Godot
UID-файлы. Кеш импорта не заменяет настройки импорта.

В TURN-001 добавлены исключения .NET bin/obj и work/artifacts. При подключении
Godot отдельным шагом дополнить точечные исключения .gitignore для:

- game/godot/.godot/;
- bin/ и obj/ проектов .NET;
- локальных IDE-файлов, work/ и artifacts/;
- локальных секретов экспорта, включая export_credentials.cfg.

Не игнорировать все *.uid или *.import. Экспортные пресеты сохраняются,
если не содержат секретов и абсолютных путей конкретной машины.

## Запуск, тесты и CI

Текущая версия продолжает использовать npm run build, npm test и существующий
веб-deploy. Для новых проектов из папки game/:

```sh
dotnet build core/Rgfn.Core.csproj
dotnet test tests/Rgfn.Core.Tests/Rgfn.Core.Tests.csproj
```

В текущем облачном окружении SDK установлен в игнорируемый work/tools/dotnet/.
Из корня репозитория его можно подключить к текущему shell:

```sh
export PATH="$PWD/work/tools/dotnet:$PATH"
export DOTNET_CLI_HOME="$PWD/work/dotnet-cli"
export NUGET_PACKAGES="$PWD/work/nuget"
cd game
dotnet test tests/Rgfn.Core.Tests/Rgfn.Core.Tests.csproj
```

На машине с установленным совместимым SDK локальная установка в work/ не нужна.
Установщик: https://dot.net/v1/dotnet-install.sh с --channel 8.0 и
--install-dir work/tools/dotnet --no-path. Этот каталог и кеши не хранятся в Git.
В окружении с ограниченным networking dotnet test требует разрешённого сетевого
доступа для первого restore и локального соединения VSTest с test host.
Godot-сцены и команды их запуска пока не созданы.

Не приводить отсутствующую команду как уже прошедшую проверку. Для каждой команды
указывать рабочую папку. Путь сохранений в Godot — пользовательское хранилище
user:// через адаптер, а не каталог репозитория.

CI новой версии добавляется отдельным workflow с закреплёнными версиями;
проверка ядра и проверка движка разделены. Добавлять его после локально работающего
маршрута сборки. Обычная сборка не публикует игру в Steam.

## Дальнейшая судьба TypeScript-версии

Во время переноса она остаётся рабочим образцом. Исправления в ней не дублируются
автоматически: задача явно указывает, какую версию меняет и нужно ли перенести
правило во вторую. Удаление или перенос текущих корневых файлов выполняется
отдельным поручением после проверки достаточности новой версии.
