# Решения и открытые вопросы

Обновлено: 12 октября 2026 года. Основания — обсуждение с пользователем,
документация прототипа и текущий код. Рабочие технические решения можно уточнять
по результатам маленьких задач; нельзя приписывать пользователю принятие
конкретной реализации, которую он ещё не ревьюил.

## D-001: объём первого релиза

Подтверждено пользователем: войны фракций и захваты деревень входят в первый
релиз. Несколько актов — дальнейшее развитие. Это уточняет широкий старый
vision; упоминание иной возможности в нём не означает обязательность для релиза.

## D-002: Godot + C# и независимое ядро

Рабочее направление итогового видения: Godot отвечает за представление и
платформу, обычный C# — за игровое состояние и правила. Причины: постоянные
сущности, автономная симуляция, сложные переходы квестов, воспроизводимость
и возможность читать/проверять маленькие части без редактора.

Проверяем направление ранним сквозным маршрутом. Если граница мешает конкретному
результату, сначала описываем проблему и корректируем необходимую часть.
Проект не превращается в универсальный движок.

## D-003: один репозиторий, новая реализация в game/

Рабочее решение: оставить TypeScript в корне и добавить game/core, game/godot,
game/tests. Это сохраняет действующие команды и веб-сборку, облегчает сравнение
механик и исключает большой перенос файлов в начале. Повторная организация
корня и удаление прототипа требуют отдельной задачи.

## D-004: данные для обычного контента, код для новых правил

Рабочее решение: определения по ID и валидация ссылок; Resource может служить
редакторским источником, загрузчик создаёт обычные определения ядра.
Общий изменяемый Resource не является конкретным предметом/NPC.
Новая механика получает простой обработчик; общей системы скриптования
и реестров для всех будущих категорий на старте нет.

## D-005: маленькие шаги с долговременным учётом

Подтверждено пожеланием пользователя: основная реализация агентом,
регулярное ревью функции/файла/небольшого поведения, появление новых правил.
Рабочая организация: один активный ID, карточка, один STATUS.md,
актуальный RULES.md, сохранение принятия и исправлений.

Маленький шаг должен быть проверяемым. Не делим необходимый тест и правило
на независимые «готовые» результаты только ради числа файлов.
Автоматическое принятие по успешным тестам не используется.

## D-006: автономность по игровому времени

Рабочая база текущей механики: мир принимает решения сам, когда действия
продвигают игровое время. Симуляция не зависит от открытой сцены и кадров.
Значимое состояние воспроизводится при эквивалентном продвижении времени.
Тактический бой и симуляция не могут одновременно владеть разрешением
одного и того же конфликта.

## D-007: NUnit для тестов C#

Подтверждено пользователем 12 октября 2026 года: использовать NUnit.
Выбор фреймворка закрыт. В BOOT-001 остаётся проверить совместимые версии
NUnit и средств запуска через dotnet test для выбранного SDK/framework.
Новый агент не выбирает тестовый фреймворк повторно.

## Что ещё решить и когда

| Вопрос | До какого шага решить | Можно ли пока продолжать |
| --- | --- | --- |
| Godot .NET, SDK, target framework, версии NUnit/средств запуска, доступные инструменты | BOOT-001 | NUnit уже выбран; документация и чтение доступны |
| Целевые ОС и обязательность браузерного экспорта | Первая проверка экспорта; браузер не обещан | Bootstrap для десктопа доступен |
| Источник определений: Resource или другой формат для конкретной категории | Первое содержательное определение | Не создавать двойной источник данных |
| Воспроизводимый RNG и сохранение его состояния | Первая игровая генерация | Детерминированные операции времени доступны |
| Стоимость боевых действий и сохранение внутри боя | Интеграция боя/времени и боевой save | Базовые правила боя доступны |
| Защитники прерывают захват: сброс/заморозка/иная политика | Правило прерывания захвата | Базовый конфликт доступен |
| Вмешательство игрока и передача владения конфликтом | Вход в живой конфликт | Автономное разрешение доступно |
| Смерть контакта/захват цели и проходимость главного квеста | Связь войн с квестами | Первые курьерские сценарии доступны |
| Смерть героя, метапрогрессия, точный объём контента | Исходы прохождения и релизный срез | Технический сквозной маршрут доступен |
| Перенос браузерных сейвов | Импорт старого формата, если назначен | Новые сейвы имеют собственный формат |

Открытый вопрос блокирует только зависимое поведение. Если ответ определяется
исходниками или обычным техническим выбором, агент исследует и фиксирует его
в порученном шаге. Существенный продуктовый выбор представляет человеку
с конкретным сценарием и вариантами до реализации зависимого правила.

## Изменение решения

Для изменения сохранить ID, причину, дату и связь с задачей/указанием пользователя.
Старое основание кратко оставить, актуальный выбор обозначить явно.
Обновить зависимые разделы пакета; не переписывать молча исторический результат
или ревью уже выполненной задачи.
